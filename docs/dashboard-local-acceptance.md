# Sitemap 监控本地控制面板 —— 本地验收清单（M2 + M3）

状态：已实现。本文档给出在真实 Windows 环境上验证站点管理功能（M2）和网页运行控制功能（M3）的具体步骤，以及配置/运行出问题时的备份/恢复/回滚方法。

> CC 沙盒（本工具运行的容器环境）没有真实 Windows 桌面和 PowerShell 运行时，不能声称已经完成真实 Windows 桌面验证——本文档第 8 节列出的步骤必须由用户在真实 Windows 机器上手工走一遍。沙盒内完成的是：全部自动化测试、PowerShell 脚本的文本级静态校验、以及用无头 Chromium 对 Dashboard 后端接口的真实 HTTP/浏览器行为验证（不涉及 Windows 专属机制，如任务计划程序、真实文件锁定行为、快捷方式图标等）。

## 1. 启动前准备

```powershell
cd <项目目录>
npm install

```

`npm test` 应显示全部通过（本阶段基准：339/339）。如果测试不通过，不要继续验收——先解决测试失败，配置写入和运行控制功能的正确性依赖这些测试覆盖的行为。

## 2. 启动面板

```powershell
.\scripts\start-dashboard.ps1
```

或者双击 `create-desktop-shortcuts.ps1` 生成的桌面快捷方式，或运行 `run-and-open-dashboard.ps1`（启动后自动打开默认浏览器）。

确认：
- 终端显示监听地址为 `http://127.0.0.1:8766`（或 `SITEMAP_DASHBOARD_PORT` 指定的端口）。
- 浏览器打开后能看到"Sitemap 监控面板"标题和"总览 / 站点管理"两个 tab。
- 页脚提示"本地专用面板，仅监听 127.0.0.1，不对局域网或公网开放"。

## 3. 站点管理黄金路径验收

按顺序操作，每一步都应该在浏览器里立刻看到对应反馈，不需要手工刷新页面（除非该步骤本身说明需要）：

1. **切到"站点管理" tab**：应看到 `config/sites.csv` 里已有的站点列表。
2. **新增站点**：点"+ 新增站点"，填 `site_id`（如 `testsite`）、`domain`（如 `testsite.example.com`），点"下一步：预览"，确认预览框里显示的 JSON 和你填写的一致，点"确认保存"。应看到"保存成功"提示，返回列表后能看到新站点。
3. **核对 CSV**：用文本编辑器打开 `config/sites.csv`，确认新增的一行确实写进去了，格式正确。
4. **编辑站点**：点新站点的"查看/编辑"，再点"编辑"，改一下"优先级"，预览、确认保存，确认列表里优先级更新了。
5. **站点级限制**：在站点详情页找到"站点级限制"区域，填一个 `max_download_bytes`（如 `10485760`），确认下方出现"约 10.0 MB"这样的可读换算，点"保存限制"。确认 `config/site-limits.csv` 里出现对应行。
6. **手工 Sitemap**：在"手工 Sitemap"区域点"+ 添加 Endpoint"，填一个合法的 `https://` 地址，点"保存手工 Sitemap"。确认 `config/site-sitemaps.csv` 里出现对应行。
7. **运行诊断**：点"运行诊断"，等待（可能需要几秒到几十秒，取决于站点大小），确认结果表格展示 discovery mode / 首页状态 / robots.txt 状态 / Endpoint 数量 / 推荐处理等字段。
8. **暂停监控**：回到详情页，点"暂停监控"，确认弹窗提示"暂停不会删除任何历史数据"，点确定。确认站点仍出现在列表中（标记为"暂停"），不是消失。
9. **恢复监控**：点"启用监控"，确认状态恢复。

## 4. 边界场景验收

| 场景 | 操作 | 期望结果 |
|---|---|---|
| 重复 site_id | 新增一个和已有站点相同的 site_id | 保存时提示字段错误，不会静默创建重复行 |
| 非法域名 | domain 填 `localhost` 或 `192.168.1.1` | 保存时提示域名不合法（SSRF 防护） |
| 手工编辑 CSV 后再从面板保存 | 面板打开着，用文本编辑器直接改 `sites.csv` 并保存，再回到面板尝试保存任意改动 | 面板保存时提示"配置已被其他操作修改，请刷新后重试"，不会覆盖手工编辑的内容；刷新面板页面后手工编辑的内容应该能看到 |
| 两个浏览器标签页同时编辑同一站点 | 开两个标签页，都打开同一站点的编辑表单并预览，其中一个先保存 | 先保存的成功；后保存的收到冲突提示，不会覆盖前者 |
| manual_only 模式下清空所有 Endpoint | 手工 Sitemap 模式选 `manual_only`，删掉所有已启用的 Endpoint 后保存 | 拒绝保存并提示"必须至少有一个已启用且合法的手工 Sitemap Endpoint" |

## 5. 备份与恢复

每一次成功的配置写入之前，服务都会在 `config/backups/<时间戳>-<随机后缀>/` 下保留修改前三份 CSV 文件的完整副本，附一个 `manifest.json` 记录每个文件写入前的哈希。

**手工恢复到某次写入之前的状态**：

```powershell
# 1. 先停止面板服务（Ctrl+C 或 stop-dashboard.ps1）
# 2. 找到要恢复的备份目录（按时间戳挑选）
dir config\backups
# 3. 把该目录下的文件复制回 config/，覆盖当前文件
copy config\backups\<时间戳目录>\sites.csv config\sites.csv
copy config\backups\<时间戳目录>\site-limits.csv config\site-limits.csv
copy config\backups\<时间戳目录>\site-sitemaps.csv config\site-sitemaps.csv
# 4. 重新启动面板——启动时会自动把 CSV 内容同步进 SQLite
.\scripts\start-dashboard.ps1
```

注意：如果某次备份的 `manifest.json` 里某个文件 `existedBefore: false`，说明写入前那个文件本来就不存在（比如第一次给某站点设置手工限制之前，`site-limits.csv` 还没被创建过）——恢复到那次备份之前的状态意味着删除该文件，而不是用备份目录里的内容覆盖（备份目录里也不会有这个文件）。

## 6. 网页运行控制（M3）常见操作

### 如何运行全部站点
在"总览"页或"实时运行"页点击"开始全部监控"，确认框会显示启用站点数量、上次全量运行耗时（如果有历史记录）、磁盘/内存提示；确认后自动跳转到"实时运行"页，实时看到每个站点的进度。

### 如何运行选中的站点
在"站点管理"页用复选框勾选（已暂停的站点无法勾选），页面显示"已选择 N 个站点"，点击"运行选中站点"，确认框会列出选中的 site_id，确认后同样跳转到"实时运行"页。

### 如何安全停止
在"实时运行"页点击"安全停止"，会看到"已提交停止请求，当前正在处理的网站完成后停止"的提示——当前正在采集的站点会正常完成并正常写入历史，后面还没开始的站点不再被调度。停止不会立即中断网络请求，也不会损坏数据库。注意：一旦所有站点都采集完毕、进入"正在分类"/"正在生成报告"阶段，"安全停止"按钮会自动隐藏（这两个阶段没有可以中途打断的逐条循环，运行会正常跑完）。

### 浏览器关闭后任务是否继续
继续。采集/分类/报告在服务端后台执行，和浏览器连接无关。重新打开面板（或刷新页面）会自动看到当前进度（如果还在跑）或最近一次运行的结果（如果已经结束）。

### 如何重新打开当前运行
刷新页面即可——如果有活动运行，会自动跳转到"实时运行"页；如果不小心切换到了其它 tab，手工点"实时运行" tab 也能看到。

### 如何查看新增 URL 和失败原因
实时运行页的站点表格里，有新增的站点会显示"查看新增"按钮，点击后分页查看每条新增 URL 的分类结果（游戏/非游戏/未知，采集刚完成、分类还没跑到时显示"待分类"）；失败或部分成功的站点在"错误"列直接显示错误摘要。

### 如何下载报告
运行完成后（进入"已完成"阶段），实时运行页下方会出现"报告"区块，列出 5 个报告文件的下载链接（`new-urls.csv`/`new-urls.json`/`new-games.csv`/`unknown-urls.csv`/`report.md`），也会显示报告所在的本地目录路径（可以直接去该目录用 Excel 打开 CSV）。**被安全停止的运行不会生成报告**（跳过了分类/生成报告阶段），这是设计行为，不是 bug。

### 如何识别异常中断
如果面板服务在某次运行中途被强制结束（断电、任务管理器强制结束进程），重新启动面板后，"实时运行"页的空闲状态会显示"上次运行异常中断（run_id=...，开始于...）"，明确提示"该记录不会自动继续"，需要手工点击"开始全部监控"开始新的运行。

### 桌面快捷方式行为
双击"运行 Sitemap 监控"快捷方式：如果面板服务还没启动，会先启动（等待健康检查通过）；然后打开浏览器直接开始全部监控并跳转到实时运行页。如果面板已经在运行、且已经有一个监控任务在进行中，会直接展示那个正在进行的任务，不会重复启动。

## 7. Windows 本地验收（分阶段，前一阶段通过才能进入下一阶段）

以下步骤必须由用户在真实 Windows 机器上手工完成，沙盒环境无法替代。每个阶段完成后再进入下一个。

```powershell
git pull
npm ci
npm test
.\scripts\start-dashboard.ps1
```

### 第一阶段：单站
在站点管理页只勾选一个熟悉的小站，点击"运行选中站点"。观察实时状态更新是否流畅，刷新页面确认运行没有被打断、页面能正确恢复到当前进度或最终结果。查看运行完成后的结果（新增 URL、报告）。

### 第二阶段：三站
分别选择一个预期会成功、一个预期会失败（比如域名拼错）、一个预期会 partial（比如提前知道会被截断限制）的站点，一起运行。验证单站失败/partial 不影响其它站点正常完成，站点表格里三种状态都能正确展示。

### 第三阶段：安全停止
选择多个站点运行，运行到一半点击"安全停止"。确认：当前站点正常完成，后续站点不再启动，`data/local.db` 没有损坏（可以用 `node bin/run.js --db-status` 检查），再次运行不受影响。

### 第四阶段：桌面快捷方式
关闭浏览器和面板进程，双击"运行 Sitemap 监控"快捷方式。确认：自动启动服务、自动打开浏览器、自动开始全部监控并跳转到实时运行页；再次点击快捷方式（此时任务仍在进行）不会重复启动第二个任务。

### 第五阶段：101 站全量运行
只有前四阶段都通过才进入这一阶段。运行全部约 101 个启用站点，记录：总耗时、峰值内存占用（任务管理器观察 `node.exe` 进程）、成功/partial/失败数量、新增 URL 总数、运行期间刷新浏览器的响应情况、安全停止的实际行为（如果测试了的话）、`data/local.db` 文件完整性（运行前后都执行 `--db-status` 对比）。

## 8. 已知残余风险（验收时应知晓，不代表验收失败）

以下场景是本里程碑明确记录、未完全解决的残余风险，详见 `dashboard-security.md` 第 7 节和 `dashboard-threat-model.md`：

- SSRF 防护只在保存配置时做静态检查，不含 DNS 解析和 HTTP 重定向时的运行时校验。
- 三份 CSV 文件的写入不是跨文件原子的：如果进程在写入过程中被强制杀死（断电、任务管理器强制结束），可能残留"部分文件已更新、部分文件还是旧内容"的中间态，需要按第 5 节手工用备份恢复。
- Windows 下如果 `sites.csv` 被 Excel 等程序独占打开，保存可能失败（会返回明确的错误提示，不会损坏文件），需要先关闭占用的程序再重试。
- 分类和报告阶段没有可以中途打断的能力：安全停止只在采集阶段（逐站循环）之间生效，一旦所有站点采集完毕、进入分类/报告阶段，点击停止不会立即生效（这两个阶段处理的只是本轮新增的少量 URL，通常很快就能跑完）。
- 三份配置文件（sites/site-limits/site-sitemaps）的写入锁和运行状态是各自独立的两套机制：配置写入用进程内 `writing` 布尔量，运行控制用 `activeRun` 引用 + `collector.lock` 文件锁——理论上可以同时进行一次配置修改和一次监控运行，两者不会互相阻塞，但目前没有专门测试"运行进行中同时修改被选中站点的配置"这种交叉场景的边界行为（比如运行中途把某个正在采集的站点暂停，不会影响这一轮已经拿到的站点列表，但会影响下一轮）。

## 9. 回滚方法

如果需要临时回退到 M2（只有站点管理，没有网页运行控制）：

```powershell
git log --oneline  # 找到 M2 完成时的 commit（本文档基准 46788ad）
git checkout <M2的commit> -- src/dashboard public/dashboard src/collect-runner.js scripts/start-dashboard.ps1 scripts/run-and-open-dashboard.ps1 scripts/stop-dashboard.ps1
git rm src/db/migrations/0004_run_mode.up.sql src/db/migrations/0004_run_mode.down.sql docs/dashboard-run-control.md docs/dashboard-live-progress.md
npm test
```

（M3 新增的文件在 M2 那个 commit 里并不存在，`git checkout <commit> -- <路径>` 对这些路径会报错，必须用 `git rm` 单独删除，不能一起塞进上面那条 `checkout` 命令。）

这只回退面板相关代码，不影响 `config/*.csv`（配置文件格式在 M3 没有变化）。`crawl_runs` 表已经应用过的 `run_mode`/`site_selection` 两列不会被这次回退撤销（SQLite 旧版本对 `DROP COLUMN` 支持不一致，和本项目其它迁移的回滚约定一致——多出来的列不用、不影响 M2 版本代码读取），回退后如果需要一个"干净"的数据库，需要单独处理，不是这条命令的职责。CLI（`bin/run.js`）在整个过程中不受影响，一直可以独立运行；由于 `runCollect()` 新增的 `onEvent`/`shouldCancel` 参数是可选且向后兼容的，即使不回退 `collect-runner.js` 也不影响 CLI 行为。
